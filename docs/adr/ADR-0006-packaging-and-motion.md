# ADR-0006: Packaging, per-module appearance and motion (Phase 9)

- Status: **Proposed** (implemented; awaiting owner review)
- Builds on ADR-0005.

## Decisions

### 1. Per-user PowerShell installer, distributed as a zip

| Option | Result |
|---|---|
| MSIX package | Needs a code-signing certificate even for side-loading, and runs packaged apps with a virtualized `%APPDATA%`. Not available here. |
| MSI with WiX, or Inno Setup | Needs a toolkit that is not installed. Downloading one adds an external build dependency. |
| **Zip with `install.ps1` and `uninstall.ps1`** | Built-in tools only. Installs per user without administrator rights, adds Start menu shortcuts and an Apps & features entry, closes a running bar with `--quit`, swaps the install folder with a rename, and never touches the settings folder. **Chosen.** |

Startup with Windows is opt-in (`-StartWithWindows`), creates a shortcut in the user's Startup folder only, and an upgrade keeps the existing choice. Uninstall keeps `%APPDATA%\windowsRICE` unless `-RemoveSettings` is given. Every folder can be redirected, and `-NoRegister` skips the registry, so the whole flow is tested in a sandbox (`scripts/package-verify.ps1`).

Builds are **not signed**. Signing needs a code-signing certificate (an OV or EV certificate from a certificate authority, or a signing service), the Windows SDK `signtool`, and a timestamp server. Until then SmartScreen warns on first run. A WiX or MSIX package is the natural next step once a certificate exists.

### 2. Icon and version information compiled with `rc.exe`, no new crates

`apps/panel/build.rs` generates a resource script (icon plus `VERSIONINFO` from the package version) and compiles it with the Windows SDK resource compiler. It links the `.res` file directly. When `rc.exe` is missing, the build continues with a warning. The icon is generated by `scripts/make-icon.ps1`, so it can be reproduced and changed.

### 3. Per-module appearance as optional module fields

Each `[[bar.modules]]` entry may override content, accent colour, background tile, text size and density. Kind-specific fields are value format (RAM, VRAM), speed unit (upload, download) and the clock's date. Unset fields use the bar style, so presets and older configurations are unchanged. The fields are validated per kind, and colour pairs are checked for 4.5:1 like the global colours.

### 4. Motion on the compositor only

Fades use DirectComposition opacity animations on the existing effect group: showing the bar, the settings window, and applying a design (from 35% to 100% in at most 200 ms). Nothing redraws during a fade, and nothing animates while idle. The only CPU-driven motion is smooth scrolling in the Design Studio: a 15 ms timer that stops as soon as the target is reached.

All motion is off when Windows' "Animation effects" is off or when `[bar] animations = false`. Hover and selection feedback are immediate; animating them would need continuous redraws of the Studio.

### 5. Font discovery once per process, off the UI thread

Reading every installed family took 8–15 ms with warm caches, but 1.5 s once in a fresh process (cold font files), which blocked the Studio window. Discovery now runs on a background thread at startup with its own DirectWrite text system, and every Studio opening uses the cached list. Fonts installed while windowsRICE runs appear after a restart.
